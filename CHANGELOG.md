# История изменений

Версии — семантические (`MAJOR.MINOR.PATCH`), единственный источник правды — файл
`VERSION` в корне репозитория. Новые записи добавляются сверху.

## [1.9.7] — 2026-09-18

Исправляющий релиз самообновления и полное обновление публичной документации проекта.

### Исправлено

- Убран запуск установщика через `cmd /c start` с ручным добавлением кавычек.
  Windows повторно экранировала их и искала несуществующий файл во временной папке.
- Проверенный установщик теперь запускается напрямую как отдельный процесс: путь
  передаётся одним необрамлённым элементом argv, а экранирование выполняет Windows.
- Добавлены regression-тесты для обычного временного пути и пути с пробелами,
  а также проверка detached-флагов Windows.

### Обновлено

- Release-зависимости обновлены до `cryptography 50.0.1` и `PyInstaller 6.22.3`;
  актуальные `PyQt6 6.11.0`, `requests 2.34.2` и `pywin32 312` сохранены.
- GitHub Actions переведены на актуальные Node 24-совместимые версии
  `checkout`, `setup-python` и `upload-artifact`.
- README, политика безопасности, руководство участника, release checklist,
  лицензии, шаблоны Issues и остальные GitHub-материалы полностью освежены.
- В репозитории оставлены только полезные исходники и документация; локальные
  кэши и старые результаты сборок удалены без затрагивания пользовательских данных.

### Важно при обновлении с 1.9.5/1.9.6

- В этих версиях находится старый повреждённый механизм запуска. Если кнопка
  обновления показывает ошибку поиска временного EXE, один раз скачайте и запустите
  установщик 1.9.7 вручную со страницы Releases. Начиная с 1.9.7 последующие
  обновления снова устанавливаются из приложения.

## [1.9.6] — 2026-09-17

Исправляющий релиз после 1.9.5: полное обновление Zapret снова доставляет все
upstream-файлы, а функциональные иконки главного экрана отображаются во всех темах.
Установка поверх 1.9.5 безопасна; пользовательские настройки и списки сохраняются.

### Исправлено

- Восстановлены иконки карточек «Автоподбор» и «Тест обхода» в светлой и
  фиолетовой темах; логика функциональных иконок больше не связана с декоративным
  отображением маскота.
- Обновление Zapret теперь объединяет проверенный release asset с исходным
  архивом тега и синхронизирует `lists`, HOSTS, IPSet, скрытую `.service`, BAT-
  стратегии, `service.bat`, бинарники и новые upstream-файлы.
- Все `lists/*-user.txt`, `config.json`, пользовательские стратегии и состояние
  игрового фильтра сохраняются. Манифест управляемых файлов удаляет только
  действительно устаревшие upstream-файлы и не трогает неизвестные локальные.
- Применение обновления сделано транзакционным: ошибка любого обязательного файла
  откатывает уже записанные изменения; неполный релиз больше не отмечается как
  установленный.
- Build-fetch теперь переносит скрытую `.service`, строго проверяет полный состав
  bundle и пишет version/SHA-маркеры без BOM.
- Обновление Telegram-прокси валидирует ограничения ZIP, устанавливает полный
  staged package атомарно, добавляет новые и удаляет исчезнувшие upstream-модули.

### Проверки

- Полный набор из 245 тестов, pyflakes, compileall, проверка уязвимостей и
  визуальный offline-аудит интерфейса выполнены успешно.

### Установка

- Требуется Windows 10/11 x64 и запуск с правами администратора для WinDivert.
- WinDivert и `winws.exe` могут вызывать ложные срабатывания антивируса.
- Используемый upstream-проект: https://github.com/Flowseal/zapret-discord-youtube

## [1.9.5] — 2026-09-17

Релиз полного аудита безопасности, обновлений и интерфейса. Установка поверх
1.9.4 безопасна; пользовательские настройки и списки сохраняются.

### Безопасность и надёжность

- Обновление Zapret теперь ограничивает размеры архива и распаковки, блокирует
  ZIP-bomb, symlink и encrypted entries, проверяет полный набор ядра до записи,
  а при ошибке восстанавливает изменённые файлы из резервной копии.
- Обновление Telegram-прокси устанавливает только полный проверенный набор
  модулей через staging и атомарную замену с rollback; исходники компилируются до
  установки, а строгая проверка TLS принудительно сохраняется.
- WebSocket-движок корректно собирает fragmented messages и отклоняет frame или
  message больше 16 МиБ.
- Самообновление приложения проверяет размер установщика по metadata,
  Content-Length и фактически полученным байтам, не допуская переполнения диска
  или запуска усечённого файла.
- `cryptography` обновлена до 50.0.0, закрывающей CVE-2026-69247; в CI добавлена
  бесплатная проверка прямых runtime-зависимостей через OSV.

### Обновления и сборка

- Build-fetch Zapret всегда получает последний полный upstream bundle, сверяет
  опубликованный SHA-256 и заменяет vendor-каталог только после полной проверки.
- Release-сборка использует закреплённые версии зависимостей; GitHub Actions
  проверяет Python 3.10 и 3.14, lint, тесты и OSV перед публикацией.
- Исправлены предупреждения Inno Setup для архитектуры и удаления задания
  автозапуска.

### Интерфейс

- Исправлен белый текст на белых карточках «Автоподбор» и «Тест обхода» в светлой
  теме; добавлен regression-тест и offline renderer всех вкладок.

## [1.9.4] — 2026-08-19

Релиз про обновление и проверку связи: скачивание больше не съедает память,
движок не убивается без причины, а проверка доступности перестала считать
страницу блокировки успехом. Новых функций нет, ставить поверх 1.9.3 безопасно.

### Исправлено

- **Обновление скачивается потоком, а не целиком в память.** Архив с обновлением
  раньше загружался одним куском: на слабой машине это давало заметный провал по
  памяти, а при обрыве связи — невнятную ошибку. Теперь файл читается частями по
  256 КБ, в окне видно прогресс в мегабайтах, а архив больше 512 МБ отклоняется
  сразу, не пытаясь занять всю память.
- **Обновление больше не выключает движок без необходимости.** Раньше перед
  распаковкой безусловно выполнялся `taskkill` по `winws.exe` и остановка службы
  WinDivert — обход отваливался даже тогда, когда ни один файл не был занят.
  Теперь это происходит только если файл действительно заблокирован, и ровно один
  раз. Удаление службы WinDivert (`sc delete`) убрано совсем: оно ломало запущенные
  сторонние программы, использующие тот же драйвер.
- **Честный отчёт о частичном обновлении.** Критичными считались все файлы из
  папки `bin`, включая текстовые списки: из-за одного пропущенного `.txt`
  обновление объявлялось неудачным. Теперь критичны только сами бинарники движка
  (`.exe`, `.dll`, `.sys`), остальное перечисляется как пропущенное.
- **Проверка доступности видит страницы блокировки.** Ответ провайдера с кодом
  451 (и родственными 495–497) засчитывался как успех, и проверка показывала
  «всё работает» на странице-заглушке. Теперь такие ответы считаются блокировкой.
- **Тест зависаний больше не падает и не крутится вхолостую.** При пустом списке
  адресов проверка завершалась делением на ноль, а повторные попытки шли подряд
  без паузы и грузили канал. Добавлены защита от пустого списка и пауза между
  попытками.
- **Автоподбор стратегии перестал путать шкалы.** Быстрый результат (0 или 1) и
  глубокий (оценка 0–100) сравнивались между собой, поэтому лучшей иногда
  оказывалась заведомо худшая стратегия. Теперь результаты ранжируются по этапу
  и только потом по оценке.

### Внутреннее

- Главное окно (1264 строки) разделено на четыре модуля: списки и службы,
  первичная настройка, управление движком, действия вкладки настроек.
- Добавлена сборка релиза в GitHub Actions: по тегу `v*` прогоняются линтер и
  тесты, собираются exe и установщик, публикуется релиз с SHA-256.

## [1.9.3] — 2026-08-19

Релиз целиком про надёжность: исправлены шесть багов, из-за которых тихо ломались
автообновление, автозапуск и запуск движка. Функциональных изменений и новых
возможностей нет, обновление безопасно ставить поверх 1.9.2.

### Исправлено

- **Обновление приложения больше не молчит на путях с пробелами.**
  Скачанный установщик запускался через `start` без кавычек, и если `%TEMP%`
  содержал пробел (типично для имени пользователя из двух слов), обновление
  просто не ставилось без внятной ошибки. Путь теперь квотируется, а команда
  идёт через `cmd /c start ""` (`start` — встроенная команда оболочки, отдельного
  `start.exe` в Windows не существует).
- **Сравнение версий понимает предрелизы.** `1.9.3-rc1` больше не считается равным
  `1.9.3`: теперь `alpha < beta < rc < релиз`, а билд-метаданные (`+build.5`) не
  влияют на старшинство. Раньше пользователь с rc-сборкой не видел выход финальной
  версии и оставался на тестовой навсегда.
- **Автозапуск не запускает программу два раза.** При включённом автозапуске
  одновременно могли жить и задание планировщика, и ключ в реестре `Run`: вторая
  копия проигрывала гонку за WinDivert и падала — выглядело как случайный краш
  после входа в систему. После успешного создания задания старый ключ `Run`
  удаляется.
- **Автозапуск не дублирует запись при откате.** Если `schtasks` отказал (нет прав),
  включался резервный путь через реестр, но функция продолжала работать дальше и
  могла перетереть свой же результат. Теперь откат завершает работу сразу.
- **Ошибки службы читаемы по-русски.** Вывод `sc.exe` и `schtasks.exe` декодировался
  как UTF-8, и в интерфейсе вместо «Отказано в доступе» показывалась кракозябра.
  Добавлено чтение в OEM-кодировке (cp866), как уже было сделано для логов winws.
- **Предупреждение о конфликте со службой реально ждёт остановки.** Пауза перед
  повторным запуском была пустышкой (таймер без действия), из-за чего движок
  иногда стартовал до того, как служба отпустила WinDivert.
- **Ошибка запуска больше не тянет за собой Telegram-прокси.** Если движок не
  запустился, программа показывала ошибку, но всё равно поднимала прокси и не
  обновляла статус — интерфейс врал, что всё работает.

### Внутренние изменения

- Добавлено 8 регрессионных тестов на всё вышеперечисленное: всего 221 тест,
  pyflakes чистый.
- Удалён мёртвый `tools/repo.py` (самодельный git на dulwich) — в проекте
  используется настоящий git.
- Починены ссылки на несуществующий `tests/test_core_logic.py` в CI, `check_lint.py`
  и GUI-тестах; в `RELEASE_CHECKLIST.md` обновлены пути к окружению разработки.
