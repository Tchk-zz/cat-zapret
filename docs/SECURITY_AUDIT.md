# Аудит безопасности и целостности Zapret GUI

**Актуально для:** 1.9.7<br>
**Дата обновления:** 2026-09-18<br>
**Исходная точка аудита:** `8d31f5b`; повторная проверка после релиза 1.9.6 — `c4e0889`<br>
**Платформа:** Windows 10/11 x64, Python 3.10 и 3.14

## Итог

Аудит охватил собственный updater, синхронизацию Flowseal Zapret bundle,
Telegram proxy, WebSocket-обработку, интерфейс, зависимости, сборку и публикацию
релиза. Критичные пути переведены на проверку до записи, staging и rollback.
Главный функциональный разрыв — обновление только стратегий без HOSTS, IPSet,
`lists`, `.service` и новых upstream-файлов — устранён в 1.9.6. В 1.9.7 исправлен
реальный production-баг запуска скачанного установщика на Windows.

## Исправленные находки

### 1. Неполная синхронизация Zapret bundle — High

**Риск:** приложение могло обновить стратегии или часть бинарников, но оставить
старые HOSTS, IPSet, `list-general`, `list-exclude`, `.service`, `utils` и другие
новые upstream-файлы. После сбоев оставалась смесь версий.

**Исправление:** updater объединяет проверенный release asset с исходным архивом
того же тега, валидирует полный core bundle и синхронизирует BAT, `service.bat`,
`lists`, HOSTS, IPSet, `.service`, `bin`, `utils` и новые файлы. Применение
транзакционное; ошибка обязательного файла восстанавливает затронутые данные.

### 2. Устаревшие upstream-файлы и риск удаления user data — High

**Риск:** простая распаковка не удаляла исчезнувшие файлы, а широкая очистка могла
стереть пользовательские списки или локальные стратегии.

**Исправление:** managed-files manifest хранит только файлы, которыми управляет
upstream. При следующем обновлении удаляются лишь записи старого манифеста,
отсутствующие в новом. `lists/*-user.txt`, конфигурация, пользовательские
стратегии, состояние игрового фильтра и неизвестные локальные файлы исключены.

### 3. ZIP bomb, path traversal и ресурсное истощение — High

**Риск:** архив мог содержать слишком много данных, опасные пути, symlink или
зашифрованные записи.

**Исправление:** введены лимиты download, количества entries, размера одного
member и общего unpacked size; запрещены encrypted и symlink entries, абсолютные
пути и выход за staging-каталог. Core bundle проверяется до остановки процессов.

### 4. Telegram proxy мог устанавливаться частично — High

**Риск:** пофайловая замена source zipball оставляла несовместимую смесь модулей,
не удаляла исчезнувшие upstream-файлы и могла отметить неполный пакет новым.

**Исправление:** полный набор распаковывается в staging, проверяется по структуре
и лимитам, каждый Python-файл компилируется, затем каталоги меняются атомарно с
backup/rollback. Удалённые upstream-модули больше не остаются в активном engine.

### 5. Небезопасные upstream TLS defaults — High

**Риск:** некоторые upstream-изменения Telegram proxy отключали проверку
сертификата и hostname.

**Исправление:** локальная интеграция принудительно сохраняет `CERT_REQUIRED` и
hostname verification. Обновление не принимает конфигурацию с `CERT_NONE`.

### 6. Неограниченные WebSocket frame и message — High

**Риск:** peer мог объявить чрезмерный payload и вызвать расход памяти; fragmented
messages обрабатывались неполно.

**Исправление:** frame и собранное message ограничены 16 MiB, размер проверяется
до чтения payload, continuation frames собираются согласно протоколу.

### 7. Самообновление могло заполнить диск или запустить неподтверждённый EXE — High

**Риск:** доверие только metadata или размеру не подтверждает содержимое; поток
без лимита способен заполнить системный диск.

**Исправление:** installer asset ограничен 512 MiB, сверяется по GitHub metadata,
`Content-Length`, фактическому числу байт и опубликованному SHA-256. При любом
несоответствии файл удаляется и не запускается.

### 8. Двойное quoting пути установщика — High

**Риск:** версии 1.9.5 и 1.9.6 передавали вручную заключённый в кавычки путь внутри
argv для `cmd /c start`. Windows экранировала кавычки повторно и искала буквальное
несуществующее имя вида `\"...ZapretGUI-Setup-....exe\"`. Короткий путь
`ADMINI~1` был нормальным и не являлся причиной.

**Исправление 1.9.7:** оболочка и ручное quoting удалены. Проверенный EXE
запускается напрямую, а raw path передаётся отдельным argv-элементом; сериализацию
выполняет `subprocess/CreateProcess`. На Windows используются detached process
flags. Тесты покрывают обычный TEMP, путь с пробелами и launch flags.

### 9. Регрессии иконок и контраста — Medium

**Риск:** функциональные иконки «Автоподбор» и «Тест обхода» зависели от флага
декоративного маскота, а дочерние labels теряли контраст в светлой теме.

**Исправление:** функциональные и декоративные элементы разделены; палитра labels
берётся из активной темы. Offline renderer проверяет Light, Purple и все вкладки.

### 10. Невоспроизводимая и устаревающая release-сборка — Medium

**Риск:** плавающие top-level зависимости и устаревший Node runtime GitHub Actions
делали сборку неповторяемой и создавали предупреждения или будущие отказы CI.

**Исправление:** release top-level packages закреплены; на 1.9.7 используются
PyQt6 6.11.0, requests 2.34.2, cryptography 50.0.1, pywin32 312 и PyInstaller
6.22.3. Actions `checkout`, `setup-python` и `upload-artifact` обновлены до
Node 24-совместимых major-версий.

## Проверки

- полный pytest: **246 тестов успешно** (включая 33 теста self-updater);
- pyflakes, OSV и compileall завершены успешно локально и являются обязательными
  повторными gates в GitHub Actions на Python 3.10 и 3.14;
- workflow проверяет соответствие `VERSION` и release tag;
- официальный installer строится только из tag и публикуется вместе с SHA-256;
- GUI рендерится offline без запуска Zapret, сети, tray или изменения config.

## Остаточные риски

1. GitHub source zipball Telegram proxy не предоставляет отдельный release digest;
   защита опирается на HTTPS/GitHub, строгую структуру, staging и compile-check.
2. Top-level pins закреплены, но полный transitive lock с hashes ещё не введён.
3. Offline GUI render не заменяет физический smoke на нескольких DPI и мониторах.
4. Install/update/uninstall необходимо периодически проверять в отдельной Windows VM.
5. WinDivert и `winws.exe` могут вызывать ожидаемые ложные срабатывания антивирусов.

## Правила дальнейших изменений

- не отключать TLS и hostname verification;
- не выполнять скачанный EXE без опубликованного SHA-256;
- не применять пакет до полной structural validation;
- не удалять user-файлы по широкому glob;
- не добавлять кавычки внутрь argv вручную;
- обновлять этот отчёт, CHANGELOG и third-party notices при изменении trust boundary.
