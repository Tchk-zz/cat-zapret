# assets_src — исходники тяжёлых картинок

Здесь лежат **оригиналы** битмапов интерфейса в том виде, в котором их отдал
дизайн (канва 5167x3750). В приложение они в таком виде не попадают.

## Зачем

Qt декодирует `QPixmap` в полном разрешении: 5167 * 3750 * 4 байта — это ~74 МБ
оперативной памяти на одну картинку. Четыре таких файла давали ~300 МБ RSS на
старте, хотя интерфейс рисует кота шириной 256 px, а фон — максимум 1240x900.

Поэтому в `ui/assets/` лежат уменьшенные копии, а оригиналы остаются здесь —
чтобы шаг был обратимым и повторяемым.

## Как пересобрать

```
python tools/optimize_assets.py --check   # показать, что изменится
python tools/optimize_assets.py           # перезаписать ui/assets/
```

Скрипт сам подбирает высоту так, чтобы значение, которое считает вёрстка
(`ui/tab_home.py`: `int(cat_w * pm.height() / pm.width())`), не изменилось ни на
пиксель — иначе кот сдвинется относительно кнопки питания.

После пересборки: `python -m pytest tests/test_home_assets.py -q` — там зашит
бюджет памяти на каждый PNG из `ui/assets/`.

## Важно

* `zapret-gui.spec` собирает только `ui/assets` (и вложенные `fonts/`, `themes/`,
  `icons/`), поэтому эта папка в exe **не** попадает и вес сборки не растёт.
* Если художник обновляет картинку — новый оригинал кладём сюда, затем
  прогоняем `tools/optimize_assets.py`.
